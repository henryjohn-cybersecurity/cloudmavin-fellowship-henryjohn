# Task 1.4 Report

## Research Methodology Statement

## Executive Summary

A Personal Research & Documentation Standard was developed to define how research, documentation, evidence management, and version control will be maintained throughout the CloudMavin Cybersecurity Fellowship. The standard establishes consistent procedures for note-taking, file naming, source citation, evidence collection, and GitHub version control.

---

## Objectives

- Establish a consistent research methodology.
- Define documentation standards.
- Standardize file naming conventions.
- Improve evidence management.
- Maintain version control using GitHub.
- Promote professional reporting practices.

---

## Methodology

The methodology was developed by identifying best practices in cybersecurity documentation and adapting them to the fellowship requirements. Standards were created for note-taking, file organization, citation, version control, evidence management, and AI-assisted learning.

---

## Technical Details

The Personal Research & Documentation Standard covers the following areas:

| Standard Area | Description |
|--------------|-------------|
| **Note-taking** | Organizing technical notes using Obsidian in a structured and consistent manner. |
| **File Naming** | Using standardized and descriptive file names for reports, screenshots, and evidence. |
| **Documentation** | Preparing technical reports using a consistent professional format. |
| **Source Citation** | Referencing official documentation and trusted cybersecurity resources. |
| **Version Control** | Using GitHub to track changes, maintain revisions, and manage project history. |
| **Evidence Management** | Organizing screenshots, command outputs, and supporting materials for each task. |
| **Backup Strategy** | Maintaining multiple backups using Obsidian, GitHub, local storage, and Google Drive. |
| **AI Usage** | Using Artificial Intelligence responsibly as a learning and documentation assistant. |

## Findings

The development of a Personal Research & Documentation Standard improves organization, consistency, traceability, and professionalism throughout cybersecurity projects. It also ensures that research, practical work, and supporting evidence remain well organized and easy to review throughout the fellowship.

---

## Risk Rating

**Low**

**Reason:**

A documented methodology significantly reduces the likelihood of losing evidence, creating inconsistent reports, omitting important information, or encountering version control issues during project execution.

---

## Recommendations

- Follow the documentation standard consistently throughout the fellowship.
- Update the standard whenever new tools or workflows are introduced.
- Back up documentation regularly using multiple storage locations.
- Review all reports before submission to ensure completeness and accuracy.
- Maintain consistent GitHub commit messages for effective version tracking.

---

## Lessons Learned

This task highlighted the importance of structured documentation, organized evidence management, and effective version control in cybersecurity projects. I also learned that maintaining a consistent documentation methodology improves collaboration, accountability, and the overall quality of technical reporting.
